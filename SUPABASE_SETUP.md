# Fade Flow - Supabase Setup Guide

## 1. Create Supabase Project

1. Go to [supabase.com](https://supabase.com)
2. Click "New Project"
3. Fill in project details and create
4. Wait for project to initialize

## 2. Get API Keys

1. In Supabase dashboard, go to **Settings → API**
2. Copy:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Add these to `.env.local` in the project root

## 3. Create Database Tables

Open Supabase SQL Editor and run the following commands:

### Create Services Table
```sql
CREATE TABLE services (
  id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  name VARCHAR(255) NOT NULL,
  duration_minutes INT NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Create Barbers Table
```sql
CREATE TABLE barbers (
  id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  name VARCHAR(255) NOT NULL,
  specialties VARCHAR(255),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

### Create Appointments Table
```sql
CREATE TABLE appointments (
  id BIGINT PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
  customer_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  barber_id BIGINT NOT NULL REFERENCES barbers(id) ON DELETE CASCADE,
  service_id BIGINT NOT NULL REFERENCES services(id) ON DELETE CASCADE,
  scheduled_time TIMESTAMP WITH TIME ZONE NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

## 5. Enable Row Level Security (RLS)

Set up basic RLS policies for public appointments:

```sql
-- Allow anyone to read appointments
ALTER TABLE appointments ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Enable read access for all users" ON appointments
  FOR SELECT USING (true);

-- Allow users to insert their own appointments
CREATE POLICY "Enable insert for authenticated users" ON appointments
  FOR INSERT WITH CHECK (auth.uid() = customer_id);

-- Allow users to update their own appointments
CREATE POLICY "Enable update for users based on customer_id" ON appointments
  FOR UPDATE USING (auth.uid() = customer_id);

-- Allow users to delete their own appointments
CREATE POLICY "Enable delete for users based on customer_id" ON appointments
  FOR DELETE USING (auth.uid() = customer_id);
```

## 6. Environment Variables

Create `.env.local` in the project root with:

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key_here
```

## 7. Install Dependencies

```bash
npm install
```

## 8. Run Development Server

```bash
npm run dev
```

Visit `http://localhost:3000` to see the app!

## 9. Test the Flow

1. **Homepage** (`/`) - View wait times and service info
2. **Sign up** (`/auth`) - Create an account
3. **Book appointment** (`/booking`) - Schedule a haircut
4. **View appointments** (`/appointments`) - See your bookings

## 10. Authentication Setup (Optional)

To enable email confirmations:

1. In Supabase, go to **Authentication → Email Templates**
2. Customize confirmation email if desired
3. Enable "Confirm email" in authentication settings

## Troubleshooting

- **"Cannot read properties of undefined"** - Check `.env.local` has correct Supabase keys
- **"RLS violation"** - Ensure RLS policies are created (see step 5)
- **Empty barbers/services list** - Run the seeding SQL (step 4)
- **Auth not working** - Verify `@supabase/supabase-js` is installed
